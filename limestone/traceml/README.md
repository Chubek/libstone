# TraceML

TraceML implements a source-located S-expression frontend and MetaKrivine
execution model. Link `Limestone::traceml` for `traceml.hpp`. Source syntax
and its AST are generated by `scripts/aurocks.pl` and `scripts/asdl.pl`.

```text
((lambda x (add x 2)) 40)
(if (lt 1 2) (mul 6 7) 0)
(begin 1 (sub 50 8))
```

Lambdas use lexical call-by-name closures. Integer primitives evaluate arguments
strictly left to right; arithmetic overflow, invalid division, malformed IR, and
unbound names return structured errors. `compile` parses and verifies the source;
`evaluate` returns a closed integer result.

`execute` shares the same evaluator and accepts `ExecutionOptions`: step/event
budgets, cancellation, trace recording, and a synchronous observer. Events preserve
source locations, argument/value identities, results, and branch decisions.
Observers receive borrowed events and must not mutate program IR.

`lower_graph` produces portable constant/return IR for a closed result.
`lower_trace` retains executed operations and explicit branch guards with source
provenance; `lower_machine_ir_checked` exposes lowering errors. The top-level
`--trace-execution` mode also retains the execution events in the module and
prints them to stderr.

```sh
printf '%s\n' '(if (lt 1 2) (add 20 22) 0)' | build/limestone-cli --trace-execution
```

The guard contract preserves the selected branch, rather than erasing metatracing
semantics during lowering. Executable guards need a backend deoptimization/
continuation contract; general closure/environment native code generation needs
runtime lowering. Portable IR output is directly inspectable and exchangeable
with D MachineIR.

Closed source programs can also use an explicit compiler target via
`limestone::run_pipeline(source, target, options)` or the C/Python
`limestone_compile_target` / `compile_target` entry points. Normal lowering
evaluates the closed program using the same lazy MetaKrivine semantics, then
selects/allocates/encodes its constant/return graph. Trace lowering requires legal
target implementations of each recorded checked operation and guard.
`tests/fixtures/native-constant.isa` declares a bounded native constant/return
slice, including fixed RAX operands, the System V x86-64 i64 return ABI and ELF
metadata. The end-to-end tests execute its emitted functions and system-linked
objects. Missing/out-of-range target patterns fail explicitly.

## C99 backend and libtraceml

`traceml-cli` emits a C99 translation unit from TraceML source. The output
contains a versioned table of lowered operations with lexical indices and
source locations, and an entry point. It neither embeds source for parsing
at runtime nor evaluates the program during compilation. The separate,
pure-C `libtraceml` runtime executes it with lazy lexical arguments and
checked integer arithmetic. Compile and link with a C compiler; there is no
C++ or Limestone pipeline dependency in the generated executable.

From the `limestone/` directory:

```sh
cmake -S . -B build
cmake --build build --target traceml-cli traceml_runtime
echo '(lambda x (add x 2))' | build/traceml-cli --module add_two -o add_two.c
```

Save this as `driver.c`:

```c
#include <traceml/runtime.h>
#include <inttypes.h>
#include <stdio.h>

extern traceml_entry_v1 traceml_generated_add_two_run;

int main(void) {
    int64_t arg = 40, result;
    traceml_error error;
    traceml_status status = traceml_generated_add_two_run(&arg, 1, NULL, &result, &error);
    if (status != TRACEML_OK) {
        fprintf(stderr, "%" PRIu32 ":%" PRIu32 ": %s\n",
                error.line, error.column, traceml_status_message(status));
        return 1;
    }
    printf("%" PRId64 "\n", result);
    return 0;
}
```

```sh
cc -std=c99 -I. driver.c add_two.c -Lbuild -ltraceml -o demo
./demo  # 42
```

The C++ emitter is `emit_c99(program, module)` in `<traceml/c99.hpp>`.
Generated C callers link the installed CMake target `Limestone::traceml_runtime`
(`libtraceml.a`); the existing compiler target is still `Limestone::traceml`
and its archive is now `liblimestone_traceml.a`. Distinct module names let
multiple generated units coexist in one binary. The default module name is
`main`; no C `main()` is generated.

To deploy only the archive and C header, run
`cmake --install build --component TraceMLRuntime --prefix /path/to/prefix`.
For that minimal installation, use `-I/path/to/prefix/include` and
`-L/path/to/prefix/lib -ltraceml` (adjust the library directory if configured
differently).

The C boundary accepts integers and requires an integer result; closures and
first-class primitives remain usable within a program. Earlier top-level
forms execute before arguments are applied to the final form. A call can
specify a step limit, an arena limit and a cancellation callback; errors
report the source site and leave the supplied result untouched. The default
limits are 100,000 source steps and 1,000,000 records per transient arena.
The C runtime does not expose tracing events or execute CESK-Theta hot traces;
that tape engine remains separate.

## CESK-Theta loop metatracing

`cesk_theta.hpp` adds a separate, typed instruction-tape runtime in
`limestone::traceml::cesk_theta`. Link the same `Limestone::traceml` target.
This is **not** a replacement for the lazy TraceML evaluator, and there is
currently no TraceLambda-to-CESK lowering. No new source syntax is required.

The instruction semantics follow the archived VMWeave
[CESK description](../../.decomissioned/lapislazuli/VMCollection/CESK/CESK.vmw):
control is a tape index, environments hold **store addresses**, `Lambda`
captures those addresses, and `Store` writes through them. `Apply1`–`Apply3`
allocate fresh argument cells; lexical index zero selects the first argument
and captured bindings follow the new arguments. `Return` restores the caller's
environment and stack base, keeping one result. `Test` sets a nonzero flag for
`Branch`; `Print` updates the last-output cell, not stdout.

The C++ tape uses signed 64-bit cells (including numeric closure handles, as
in the archive), with wrapping add/subtract/multiply/negate and checked signed
division. Apply instructions have no unused label operand: the closure itself
chooses the target. Callees cannot consume the caller's operand stack, and
falling off the tape without `Stop` is an error. There is no store or closure
reclamation. The runtime bounds storage to 512 operand cells, 256 store cells,
64 lexical bindings per environment, 64 closures and 128 continuations.

```cpp
#include <traceml/cesk_theta.hpp>

namespace cesk = limestone::traceml::cesk_theta;

int main() {
  using enum cesk::Opcode;
  const cesk::Program code{
    {Constant, 8}, {Lambda, 4}, {Apply1}, {Stop},
    {Load, 0}, {Constant, 1}, {Sub}, {Store, 0},
    {Load, 0}, {Test}, {Branch, 4, 11}, {Load, 0}, {Return},
  };
  cesk::ExecutionOptions options;
  options.hot_threshold = 1;
  auto run = cesk::execute(code, {}, options);
  return !run || run.value().state.stack.back() != 0 ||
    run.value().completed_trace_iterations == 0 || run.value().side_exits.size() != 1;
}
```

The interpreter counts arrivals on backward `Jump`/`Branch` edges. A hot
header records one path of real machine transitions; a path that comes back to
the header before the length budget expires is verified and compiled to a
portable array of prebound operation handlers. The tape identity, instruction
operands, and recorded path are static (“green”); stack values, environments,
store contents, and continuations stay live (“red”). Future entries execute the
handlers directly without decoding each tape opcode. No results or store
addresses from the recording run are baked into the trace.

The trace checks the flag at conditional branches, the live callee's code
address at `Apply`, and the live continuation's return address at `Return`.
A failed guard leaves that instruction unexecuted and resumes the interpreter
at its PC using the current complete state; prior operations remain committed
and are never replayed. The trace is kept for later entries. `ExecutionResult`
exposes the final state, installed paths, side exits, and per-tier guest-step
counts. The same budget and cancellation policy applies to both tiers; a guard
that fails and falls back consumes only one guest step. A zero threshold, trace
length limit, or trace-count limit disables metatracing.

This slice has one recording attempt and at most one trace per header, with no
side-exit bridges, recursion hotness, cross-run trace cache, native code emission,
or CLI/C entry point. It runs executable portable traces; it makes no claim of
native JIT compilation or speedup.
