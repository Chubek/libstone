# Generating artifacts with Perl extensions

LLSynth extensions consume the validated `.llsynth` model, including declarations
from includes and imports. They run in the generator; the resulting files do not
require Perl. From the repository root:

```sh
driver=cornerstone/LLSynth/scripts/llsynth.pl
spec=cornerstone/LLSynth/addons/examples/tiny.llsynth
perl "$driver" --list-extensions
perl "$driver" --extension VimGen --out-dir build/vim "$spec"
perl "$driver" --extension PrettyPrint -o tiny-reference.tex "$spec"
perl "$driver" --extension GrammarGraph -o tiny.dot "$spec"
```

| Name | Default output | Contents |
| --- | --- | --- |
| `VimGen` | `syntax/<stem>.vim`, `indent/<stem>.vim` | Syntax and indentation for programs written in the specified language |
| `PrettyPrint` | `<stem>.tex` | Standalone LaTeX reference: metadata, start rule, token/skip definitions, types, functions, grammar and action facets |
| `GrammarGraph` | `<stem>.dot` | Graphviz rule-reference graph, with the start rule drawn as a double circle |

The filename stem comes from `.language`: `Tiny & Co` becomes `tiny_co`.
Repeat `--extension` to generate several sets of artifacts in one invocation.
`--out-dir` creates the output tree. `-o` renames a single artifact and
requires its parent directory to exist. `--manifest FILE` records output paths
and SHA-256 digests. Extension mode defaults to `--mode=analyze`, so a
grammar-only specification needs no dummy lowering or interpreter facet.
`--check` validates and exits before writing artifacts.

### Using the outputs

For Vim, run `:set runtimepath^=/absolute/path/to/build/vim`, enable
`:syntax enable` and `:filetype indent on`, then `:setlocal filetype=tiny`
in a program buffer. To select it automatically, associate the desired suffix
in your vimrc, e.g. `autocmd BufRead,BufNewFile *.tiny setfiletype tiny`.
The [existing editor addons](../addons/README.md) highlight `.llsynth` files
themselves.

VimGen matches keyword and operator literals (including inline grammar
literals), translates token patterns to Vim matches, and links token groups
to `Number`, `String`, or `Identifier`. Highlighting is an editing aid: Vim
uses character regexes and match priority rather than the generated byte
lexer's longest-match algorithm. Whitespace and comment skip patterns are
not highlighted. Indentation increases after a trailing opener and decreases
before a leading closer for `()`, `[]`, and `{}` pairs present in the spec.
It does not parse strings, comments or nested expressions.

To render the other artifacts with optional external tools:

```sh
pdflatex tiny-reference.tex
dot -Tsvg tiny.dot -o tiny.svg
```

PrettyPrint escapes LaTeX metacharacters in spec text. For specifications
using a broader Unicode repertoire, use a Unicode-capable LaTeX engine and
font. GrammarGraph shows edges between declared rules, including references
inside EBNF groups, rather than generated parser states or productions.

### Adding a Perl extension

Save the following as `my-extensions/RuleNames.pm`:

```perl
package LLSynth::Extension::RuleNames;
use strict;
use warnings;

sub render {
    my ($spec, $stem) = @_;
    return { "$stem-rules.txt" =>
        join('', map { "$_->{name}\n" } @{$spec->{rules}}) };
}
1;
```

```sh
perl "$driver" --extension-path my-extensions --list-extensions
perl "$driver" --extension-path my-extensions --extension RuleNames "$spec"
```

Modules are discovered by filename in LLSynth's `extensions/` directory and
each `--extension-path DIR`. Names are case-sensitive ASCII letters, digits
and underscores, starting with a letter. Duplicates are errors. Listing uses
filenames only; selecting a module loads it as Perl code in the generator
process. Use trusted module directories.

`render($spec, $stem)` treats the model as read-only and returns a nonempty
hashref mapping relative artifact names to **Perl character strings**. The
driver encodes UTF-8, checks output collisions and writes the files. Path
components may contain ASCII letters, digits, `-`, `_` and internal dots.
Common model fields are `language`, `start`, `tokens` (array of hashes with
`name`, `regex`, `type`), and `rules` (array of hashes with `name` and a
`facets` hash containing `syntax` and any supplied actions).

Keep `scripts/LLSynthExtensions.pm` and the sibling `extensions/` directory
with the generator when installing extension support.
