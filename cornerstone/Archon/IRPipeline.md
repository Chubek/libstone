# Generated C pipeline

Every `archon irgen IR` form emits a shell-free C99 driver for the path from
that representation's checked `Program.i` to target assembly. The driver links
stage APIs directly; it never constructs or executes a command line.

## Build

For a generated directory:

```sh
cc -std=c99 -Wall -Wextra -Werror -pedantic \
  -DARCHON_IR_PROGRAM_FILE='"Program.i"' \
  -DARCHON_ISEL_NO_MAIN \
  -DARCHON_REGALLOC_NO_MAIN \
  IR.c Graphs.c Oracle.c Rewrite.c ISel.c Pipeline.c ISched.c \
  Regalloc.c Emitter.c Driver.c \
  -o archon-pipeline
```

The shared `ARCHON_IR_PROGRAM_FILE` definition opts the selected IR runtime
into compiling its representation-specific X-macro input.
`ARCHON_ISEL_NO_MAIN` and `ARCHON_REGALLOC_NO_MAIN` disable the standalone
selector and allocator CLIs when linked into the driver. `Graphs.c` is required
by the rewrite runtime and Memory SSA. `Oracle.c` is generated by default; it
is inert when no runtime Oracle endpoint is configured.

## C11 embedding API

Every full IR generation also emits `ArchonEmbed.h` and `ArchonEmbed.c`.
Applications can link these instead of `Driver.c`; no `main`, argument parsing,
environment lookup, or process-global mutable configuration is involved:

```sh
cc -std=c11 -Wall -Wextra -Werror -pedantic-errors \
  -DARCHON_IR_PROGRAM_FILE='"Program.i"' \
  -DARCHON_ISEL_NO_MAIN -DARCHON_REGALLOC_NO_MAIN \
  IR.c Graphs.c Oracle.c Rewrite.c ISel.c Pipeline.c ISched.c \
  Regalloc.c Emitter.c ArchonEmbed.c application.c \
  -o application
```

The facade remains strict-C99 compatible. If generation used
`--no-oracle`, omit `Oracle.c`; `ArchonEmbed.h`, `Emitter.h`, and `Pipeline.h`
then expose no `ArchonOracle*` type or Oracle link dependency.

```c
#include "ArchonEmbed.h"

int compile_embedded_program(void) {
    ArchonEmbedOptions options;
    ArchonEmbedResult result;

    archon_embed_options_init(&options);
    options.rewrite = ARCHON_EMBED_REWRITE_EGRAPH;
    options.dialect = ARCHON_EMBED_DIALECT_GAS;
    options.stop_after = ARCHON_EMBED_STAGE_EMIT;
    options.output_path = "output.s";
    options.artifact_policy = ARCHON_EMBED_ARTIFACTS_DISCARD;

    return archon_embed_run(&options, &result) ==
        ARCHON_EMBED_STATUS_OK ? 0 : 1;
}
```

`ArchonEmbedResult` reports the facade and low-level pipeline statuses, the
reached/failed stage, emitter status and artifact line, cleanup count, output
and retention flags, and a NUL-terminated diagnostic bounded to
`ARCHON_EMBED_MAX_DIAGNOSTIC_BYTES`. Set
`ARCHON_EMBED_ARTIFACTS_RETAIN` to inspect generated intermediates after a
stopped or complete run. Both policies first remove stale fixed-name
intermediates; neither removes the embedded `Program.i` or successful assembly
output. `archon_embed_cleanup_intermediates` performs that exact cleanup
explicitly. Artifact and output paths are relative to the caller's working
directory. Because intermediate names are fixed, applications must serialize
calls that use the same working directory.

Oracle-enabled generation adds
`const ArchonOracleOptions *oracle` to `ArchonEmbedOptions`. Initialize it with
`archon_oracle_options_init` and assign it explicitly. A `NULL` pointer or an
options value with a `NULL`/empty socket is inactive; the embedding facade never
consults `ARCHON_ORACLE_SOCKET`.

Run the complete pipeline:

```sh
./archon-pipeline --dialect gas
./archon-pipeline --dialect sandstone --output Program.asm
./archon-pipeline --rewrite egraph --keep-artifacts
ARCHON_ORACLE_SOCKET=/tmp/opencode/oracle.sock \
  ./archon-pipeline --keep-artifacts
```

The environment variable is a generated-driver convenience; the public
`Oracle.c` API takes an explicit `ArchonOracleOptions` value. An unset or empty
socket keeps every Oracle boundary inactive.

Useful driver options:

```text
--stop-after decode|rewrite|schedule|isel|isched|regalloc|emit
--rewrite conventional|egraph
--keep-artifacts
--list-artifacts
--clean
```

`--clean` preserves `Program.i`, because it is an input. A successful complete
run removes intermediate artifacts unless `--keep-artifacts` is present.

## Artifact contracts

| Stage | Artifact | Contract |
| --- | --- | --- |
| decode | source `Program.i` | Checked, representation-specific X-macros |
| rewrite | `Rewritten.i` | Rewrite-engine statistics and conservative equivalence status |
| schedule | `MIR.i` | Canonical Macro ABI v1 MachineIR stream |
| isel | `Selected.i` | Selected operation and typed operand records |
| isel | `InstrMap.i` | Canonical Macro ABI v1 instruction map |
| isched | `Scheduled.i` | Canonical schedule with SAT/fallback provenance |
| isched | `RegMap.i` | Canonical register/lifetime map |
| regalloc | `Regallocated.i` | Canonical allocation facts plus emission records |
| emit | `Program.s` / `Program.asm` | GAS or Sandstone source |

An Oracle worker may return a validated transformation and a sidecar annotation
stream for any `.i` artifact. Annotation sidecars use typed
`ARCHON_ORACLE_*` macro records. Stage consumers recognize only bounded,
stage-specific keys; unknown records are preserved or ignored and cannot make
an illegal selection, scheduling decision, allocation, or assembly operand
valid.

The public `Pipeline.h` APIs
`archon_pipeline_emit_program(FILE *, char *, size_t)` and
`archon_pipeline_emit_mir(FILE *, char *, size_t)` normalize the checked native
input into canonical Macro ABI v1 `ARCHON_PROGRAM_*` and `ARCHON_MIR_*`
streams. They write to a caller-owned stream and do not overwrite the native
`Program.i`.

For lower-level hosts, `archon_pipeline_options_init`,
`archon_pipeline_result_init`, and `archon_pipeline_run_with_result` expose the
same execution engine with a fixed-capacity `ArchonPipelineResult`.
`archon_pipeline_run` remains the compatible integer-returning wrapper.

The final emission section is:

```text
REGALLOC_EMISSION_BEGIN(instruction_count)
REGALLOC_LABEL(id)
REGALLOC_INSTRUCTION_BEGIN("OPCODE", operand_count)
REGALLOC_OPERAND_REGISTER(id)
REGALLOC_OPERAND_IMMEDIATE(value)
REGALLOC_OPERAND_LABEL(id)
REGALLOC_OPERAND_SYMBOL("name")
REGALLOC_INSTRUCTION_END()
REGALLOC_EMISSION_END()
```

`Emitter.c` parses this file at runtime. It validates instruction names,
operand count and kind, register bounds, immediate widths, symbols, duplicate
labels, and unresolved label references. A failed emission removes the partial
assembly output.

## Current integration boundary

`Pipeline.c` owns a typed adapter for all eight IR forms. It never casts one
representation's `IR.h` layout as another. ANF, Gated SSA, Memory SSA, Sea of
Nodes, Typed TAC, and Untyped TAC can lower straight-line integer examples
through emission. CPS and supercombinators decode and verify too, but reject
operations for which those forms do not carry a validated primitive
equivalence or explicit target identity.

The rewrite stage calls the generated `Rewrite.c` directed or equality-
saturation engine. Because the current ArchDB has no proof-result field, the
linked bridge records equivalence as unknown and retains the verified neutral
view rather than claiming a transformed program is proved. Instruction
selection calls the generated `ISel.c` e-graph/cost extractor through its
in-memory operation API; it does not infer behavior from instruction names.

Every driver treats `Regallocated.i` as an emitter restart point when no
`Program.i` is present.

The standalone rewrite runtime consumes the Sea-of-Nodes `Program.i`.
The standalone generated selector also understands the scheduler's MachineIR
v2 schema through `ARCHON_MIR_FILE`. The linked driver instead uses narrow
in-memory correctness-preserving adapters:

- rewrite runs the selected bounded engine, preserves the verified neutral view
  while proof status is unavailable, and records equivalence as unknown;
- selection passes neutral-view operand kinds to exact ArchSem-derived e-graph
  patterns while retaining canonical `MIR.i` as the lowering artifact;
- calls, spills, tied operands, and operations without a legal target
  instruction are rejected with diagnostics.
- multi-block inputs are rejected by canonical normalization and executable
  selection until their control-flow transitions have validated lowering
  facts; blocks are never silently linearized.

This avoids pretending incompatible peer artifacts compose while retaining a
working path for supported straight-line integer programs.

## Sandstone

Sandstone output contains ordinary target assembly plus a `<: ... :>` Lua
prelude that checks `lsandas.symas.targets` when SymAS metadata is loaded. It
does not synthesize an architecture plugin or bypass Sandstone's target
metadata. Targets without validated Sandstone syntax are rejected unless an
`Emitter_Hooks` implementation supplies the dialect.
