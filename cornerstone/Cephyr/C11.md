# ISO C11 implementation status

Cephyr uses ISO/IEC 9899:2011 as its language reference. It implements a
subset, not a conforming hosted or freestanding implementation under clause 4.
`-std=c11` selects the implemented dialect; `-ffreestanding` changes translation
mode, not the set of language features or which runtime gets linked. The
`__STDC_VERSION__` and `__STDC_HOSTED__` macros identify those modes and are not
statements of conformance.

## Environment and target choices

The three bundled Linux targets use little-endian LP64. In the supported integer
model, `CHAR_BIT` is 8 and `short`, `int`, `long`, and `long long` are 16, 32,
64, and 64 bits, respectively. Data pointers are 64 bits. Integer types use
two's-complement representation. Plain `char` is signed on AMD64 and unsigned
on AArch64 and RV64IM. Integer limit macros and typedefs are supplied by the
bundled `<limits.h>` and `<stdint.h>`.

Right shifts of negative signed integers fill with the sign bit. Conversions
to signed integer types that cannot represent the source value retain the
destination-width low bits and interpret them as two's-complement.
In a preprocessing condition, an ordinary character constant from a single
byte is interpreted as an unsigned byte value before integer evaluation.
In a C expression, a single-byte character constant instead follows the
target's plain `char` signedness.

In hosted mode, Cephyr supports definitions equivalent to `int main(void)` and
`int main(int, char **)`. Falling off the end of `main` returns zero. The
bundled CRT passes the Linux argument vector and calls `exit` when `main`
returns; this runs registered `atexit` handlers. With a different CRT or no
runtime, program startup and termination are the responsibility of that
environment.

The C11 optional-feature macros for complex arithmetic, atomics, threads, and
variable-length arrays are defined with value `1` and, like the other standard
predefined macros, are not configurable. Real floating point is also missing
from native lowering; C11 has no conditional-feature macro that makes its
absence conforming. See the [runtime inventory](stdlib/README.md) for available
headers and library functions.

## Verification and limits

`cephyr.c11-sample` combines selected §5.2.4.1 limits in one program: nested
blocks, parenthesized declarators and expressions, significant identifier
lengths, macro counts and arguments, 127 function parameters and arguments,
include depth, concatenated literal size, and a 65,535-byte static object.
It also checks §5.1.2.2 startup and normal termination with two independently
compiled translation units, as well as assertion diagnostics, file positioning,
pushback, and wide character classification through the bundled runtime.
It links on all bundled targets and executes on matching hardware or with the
configured emulators.

This is a regression test, not a conformance suite. Known limits include the
256-block limit per native MachineIR function, the 64 KiB stack-frame limit on
AMD64 and AArch64, and incomplete support for aggregate types, declarations,
and expressions. Further limitations are listed in the [README](README.md#current-limits).

| C11 clauses | Coverage and known gaps |
| --- | --- |
| §5.1.1.2, §6.10 | Trigraphs, line splicing, macro expansion, inclusion, line remapping and basic pragmas are implemented. Unicode source and identifier handling and `STDC` pragma placement are incomplete. |
| §6.2–§6.9 | Native integer and pointer code, fixed-signature calls, scalar variadic calls, fixed arrays and control flow are supported. Missing areas include general floating-point code, by-value aggregate ABI, variably modified types, designated initializers, `_Generic`, and wide literals. |
| Clause 7 | The static Linux runtime provides a subset of the library, including buffered narrow streams and C-locale wide classification. Formatted input, general wide I/O, math, time, signals, and nonlocal jumps are among the missing areas. |
