# ISO C11 implementation status

Cephyr uses ISO/IEC 9899:2011 as its language reference (the repository-local
copy is `.info/c11-std.txt`). It implements a
subset, not a conforming hosted or freestanding implementation under clause 4.
`-std=c11` selects the implemented dialect; `-ffreestanding` changes translation
mode, not the set of language features or which runtime gets linked. The
`__STDC_VERSION__` and `__STDC_HOSTED__` macros identify those modes and are not
statements of conformance.

## Environment and target choices

The three bundled Linux targets use little-endian LP64. In the supported integer
model, `CHAR_BIT` is 8 and `short`, `int`, `long`, and `long long` are 16, 32,
64, and 64 bits, respectively. Data pointers are 64 bits. Integer types use
two's-complement representation. Plain `char` is signed on AMD64 and unsigned
on AArch64 and RV64IM. `wchar_t` is 32 bits, unsigned on AArch64 and signed on
AMD64 and RV64IM. Integer limit macros and typedefs are supplied by the
bundled `<limits.h>` and `<stdint.h>`.

Right shifts of negative signed integers fill with the sign bit. Conversions
to signed integer types that cannot represent the source value retain the
destination-width low bits and interpret them as two's-complement.
In preprocessing conditions and C expressions, an ordinary single-byte
character constant follows the target's plain `char` signedness.
Other ordinary character constants pack
their UTF-8 execution bytes in spelling order, retaining the last four
bytes. `L`, `u`, and `U` character constants retain the last code unit of
their respective UTF-32, UTF-16, and UTF-32 encodings. Numeric escapes
specify code units directly.

Ordinary and `u8` strings use UTF-8; `L`, `u`, and `U` strings use UTF-32,
UTF-16, and UTF-32 respectively. Unprefixed tokens adopt the prefix of a
concatenated sequence; different explicit wide prefixes are rejected.
Numeric escapes are range-checked against the original token's element
width before concatenation. Literal encodings do not depend on the
runtime locale, whose multibyte conversions remain ASCII-only.

Source files use UTF-8. In macro names and local identifiers, direct spelling
and universal character names denote the same code points, subject to the
C11 Annex D ranges. Distinct code-point sequences are not normalized.
Stringizing preserves a universal character name's original spelling and
does not add a backslash before its introducer.

In hosted mode, Cephyr supports definitions equivalent to `int main(void)` and
`int main(int, char **)`. Falling off the end of `main` returns zero. The
bundled CRT passes the Linux argument vector and calls `exit` when `main`
returns; this runs registered `atexit` handlers. With a different CRT or no
runtime, program startup and termination are the responsibility of that
environment.

The C11 optional-feature macros for complex arithmetic, atomics, threads, and
variable-length arrays are defined with value `1` and, like the other standard
predefined macros, are not configurable. AMD64 SysV and AArch64 AAPCS64 have
native scalar `float` (binary32) and `double` (binary64); Cephyr defines its
nonstandard `__CEPHYR_HAS_SCALAR_FP` macro for these built-in providers.
RV64IM LP64 supports binary32 and binary64 storage, static initialization,
fixed-prototype calls, negation, comparisons, arithmetic, and numeric
conversions without hardware FP instructions. Arithmetic and conversions
use compiler-runtime helpers supplied by the bundled runtime. RV64IM
floating-point variadic calls remain unsupported. On SysV AMD64,
`long double` has its own 80-bit representation in
16-byte objects. Cephyr supports literals, layout, scalar access and
initialization, arithmetic, comparisons, and conversions to and from
`float`, `double`, and integers through 64 bits. By-value and variadic
calls remain unsupported. Other targets do not
yet support `long double`. Nonzero decimal `long double` literals currently
need a compatible Linux x87 build host; hexadecimal literals do not.
Annex F remains unsupported. See the
[native FP details](docs/NATIVE_FP_WIRING.md).
See the [runtime inventory](stdlib/README.md) for available headers and
library functions.

## Verification and limits

`cephyr.c11-sample` combines selected §5.2.4.1 limits in one program: nested
blocks, parenthesized declarators and expressions, significant identifier
lengths, macro counts and arguments, 127 function parameters and arguments,
include depth, concatenated literal size, a 65,535-byte static object,
1,023 switch case labels with runtime dispatch, 1,023 structure members,
1,023 enumerator declarations, and 63 nested structure definitions.
`cephyr.c11-enums` separately exercises enumerator values in constant
expressions and runtime code, enum type identity, scope, and constraint
diagnostics. Enumeration constants have type `int`, and the compatible
integer type for each completed enumeration type is signed `int`.

`cephyr.c11-alignment` covers `_Alignas` on objects and record members,
`_Alignof`, `max_align_t`, and integer-constant-expression `offsetof` with
nested named members and constant in-bounds array subscripts. Fundamental
alignments through 16 bytes are supported; alignments greater than 16 bytes
are not. Object redeclarations are checked within a translation unit.

`cephyr.c11-volatile` checks scalar volatile accesses, including scalar
members of volatile records. Evaluated scalar accesses emit width-specific
loads and stores, including discarded reads, in the same order with and
without the tested QML passes. Unevaluated operands do not access storage.
`cephyr.c11-volatile-aggregates` checks supported whole-object accesses.
Structure copies access members in address order, skip padding and flexible
array elements, and finish reading the source before writing the destination.
Whole copies of unions with intrinsically volatile members and overlapping
designators in volatile automatic initialization are diagnosed.

`cephyr.c11-frontend` checks the types and values of character constants and
the evaluation of `_Static_assert` in structure and union member lists.
`cephyr.c11-strings` checks `L`, `u`, `U`, and `u8` string literal storage,
types, concatenation, and array initialization.
`cephyr.c11-bitfields` checks layout and interoperability with Clang for
nonvolatile `_Bool`, `int`, `signed int`, and `unsigned int` fields. This
includes unnamed and zero-width fields, promotions, and initialization.
Volatile bit-field accesses and bit-field records at by-value ABI
boundaries remain unsupported.
`cephyr.c11-compound-literals` checks lvalue and postfix behavior,
designated initialization, array bound inference, and object lifetime for
file-scope and block-scope compound literals (§6.5.2.5). Static address
expressions and by-value aggregate calls still have their usual limits.

`cephyr.c11-amd64-stdarg` and `cephyr.c11-aarch64-stdarg` check variadic
interoperability with external C for promoted integer, pointer, and `double`
arguments. RV64IM definitions remain unsupported. Indirect variadic calls
and variadic aggregate and `long double` arguments are not supported.
`cephyr.c11-record-abi` checks RV64IM LP64 fixed-prototype interoperability
with Clang for supported complete structures and unions with integer or
pointer members, including two-word values and larger records passed
indirectly. Flexible arrays, anonymous members, and volatile members are
excluded. The other bundled targets do not yet lower by-value aggregate
calls or returns.
`cephyr.c11-linkage` uses multiple translation units to check block-scope
`extern` and external-linkage `inline`. Inline-only definitions are checked
but do not emit an external symbol; calls and addresses use the external
definition.
`cephyr.c11-static-fp` checks target-width rounding, signed zeros, subnormal
values, conversions, and short-circuit evaluation in AMD64 and AArch64
static initializers. `cephyr.c11-signals` checks C signal dispositions,
synchronous `raise`, external delivery, and `abort` with Cephyr-generated
callers.

The sample also checks §5.1.2.2 startup and normal termination with two independently
compiled translation units, as well as assertion diagnostics, file positioning,
pushback, and wide character classification through the bundled runtime.
It links on all bundled targets and executes on matching hardware or with the
configured emulators.

This is a regression test, not a conformance suite. The native MachineIR
verifier bounds functions to 4,096 basic blocks, with separate instruction,
value, and verification-work limits. Other known limits include the 64 KiB
stack-frame limit on AMD64 and AArch64 and incomplete support for aggregate
types and ABI.
Further limitations are listed in the [README](README.md#current-limits).

| C11 clauses | Coverage and known gaps |
| --- | --- |
| §5.1.1.2–3, §6.4, §6.10 | Trigraphs, line splicing, macro expansion, inclusion, line remapping and basic pragmas are implemented. Expanded C tokens are checked for malformed and out-of-range literal escapes, empty character constants, and concatenation of UTF-8 with wide string literals. Preprocessing conditions use `intmax_t`/`uintmax_t` conversions, short-circuit evaluation, and target `char` and `wchar_t` signedness. `#line` decodes filename escapes consistently with source maps. UTF-8 and universal character names can spell macro and local identifiers; file-scope object and function names remain ASCII-only. `STDC` pragma state is incomplete. |
| §6.2–§6.9 | Native integer and pointer code, enums, fixed-signature calls, direct integer/pointer variadic calls, fixed arrays, `_Generic` for supported types, and control flow are supported. AMD64 and AArch64 support scalar variadic definitions and direct scalar FP variadic calls. Records support native storage, member access and initialization, including [anonymous structures and unions](docs/C11_ANONYMOUS_MEMBERS.md) and nonvolatile bit-fields, plus the limited by-value ABI described above. Scalar and supported aggregate volatile accesses, wide character constants, and wide string literals are implemented. Variably modified types remain unsupported. |
| Clause 7 | The static Linux runtime includes C signal handling, floating-environment functions on AMD64 and AArch64, buffered narrow streams, wide strings, UTC calendar/time functions, and C-locale character conversions and classification. Wide `printf` and `scanf` support nonfloating conversions. Narrow `printf` supports binary64 formatting, and narrow `scanf` reads `float` and `double`. Narrow and wide binary32/binary64 text conversion is implemented; native declaration availability depends on the frontend ABI. Wide floating formatted I/O, `%L` formatting, `strtold`/`wcstold`, and math remain missing. The archive's nonlocal jumps are for externally compiled C; the Cephyr frontend does not model returns-twice calls. |

Other confirmed language gaps include nested composite types (§6.2),
parameter-array qualifiers and `static` bounds (§6.7), and
old-style function definitions (§6.9.1). See the
[runtime inventory](stdlib/README.md#remaining-c11-conformance-blockers)
for clause-by-clause library blockers.

## Conformance milestones

1. **Freestanding language and headers (clause 4):** Cover the mandatory
   language constructs on each claimed target, including `long double`,
   full aggregate calls and returns, remaining aggregate volatile access
   cases, and variadic function definitions with `<stdarg.h>` on all claimed
   targets. Keep the §5.2.4.1 translation and
   execution fixture passing while expanding its semantic coverage. C11
   allows the documented §6.10.8.3 opt-outs for conditional features, not
   opt-outs for these mandatory facilities.
2. **Hosted library and startup (clauses 5 and 7):** Complete the required
   library for the features each target claims, and verify it end to end
   with Cephyr-generated callers, not just the compiler that builds the
   runtime archive. Freestanding conformance would not imply hosted
   conformance.
3. **Diagnostics and implementation choices:** Check syntax and constraint
   diagnostics (§5.1.1.3) and document implementation-defined behavior,
   locale choices, and extensions (clause 4 and Annex J). Do not treat the
   predefined macros or a passing regression suite as evidence of complete
   conformance.
