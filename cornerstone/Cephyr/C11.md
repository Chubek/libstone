# ISO C11 implementation status

Cephyr uses ISO/IEC 9899:2011 as its language reference. It implements a
subset, not a conforming hosted or freestanding implementation under clause 4.
`-std=c11` selects the implemented dialect; `-ffreestanding` changes translation
mode, not the set of language features or which runtime gets linked. The
`__STDC_VERSION__` and `__STDC_HOSTED__` macros identify those modes and are not
statements of conformance.

## Environment and target choices

The three bundled Linux targets use little-endian LP64. In the supported integer
model, `CHAR_BIT` is 8 and `short`, `int`, `long`, and `long long` are 16, 32,
64, and 64 bits, respectively. Data pointers are 64 bits. Integer types use
two's-complement representation. Plain `char` is signed on AMD64 and unsigned
on AArch64 and RV64IM. Integer limit macros and typedefs are supplied by the
bundled `<limits.h>` and `<stdint.h>`.

Right shifts of negative signed integers fill with the sign bit. Conversions
to signed integer types that cannot represent the source value retain the
destination-width low bits and interpret them as two's-complement.
In a preprocessing condition, an ordinary character constant from a single
byte is interpreted as an unsigned byte value before integer evaluation.
In a C expression, a single-byte character constant instead follows the
target's plain `char` signedness.

Source files use UTF-8. In macro names and local identifiers, direct spelling
and universal character names denote the same code points, subject to the
C11 Annex D ranges. Distinct code-point sequences are not normalized.
Stringizing preserves a universal character name's original spelling and
does not add a backslash before its introducer.

In hosted mode, Cephyr supports definitions equivalent to `int main(void)` and
`int main(int, char **)`. Falling off the end of `main` returns zero. The
bundled CRT passes the Linux argument vector and calls `exit` when `main`
returns; this runs registered `atexit` handlers. With a different CRT or no
runtime, program startup and termination are the responsibility of that
environment.

The C11 optional-feature macros for complex arithmetic, atomics, threads, and
variable-length arrays are defined with value `1` and, like the other standard
predefined macros, are not configurable. AMD64 SysV and AArch64 AAPCS64 have
native scalar `float` (binary32) and `double` (binary64); Cephyr defines its
nonstandard `__CEPHYR_HAS_SCALAR_FP` macro for these built-in providers. RV64IM
LP64 does not lower floating-point objects or values. [Native FP details](docs/NATIVE_FP_WIRING.md)
describe supported operations and limits, including unsupported `long double`,
FP variadics, general static FP constant expressions, and Annex F.
See the [runtime inventory](stdlib/README.md) for available headers and
library functions.

## Verification and limits

`cephyr.c11-sample` combines selected §5.2.4.1 limits in one program: nested
blocks, parenthesized declarators and expressions, significant identifier
lengths, macro counts and arguments, 127 function parameters and arguments,
include depth, concatenated literal size, a 65,535-byte static object,
1,023 switch case labels with runtime dispatch, 1,023 structure members,
1,023 enumerator declarations, and 63 nested structure definitions.
`cephyr.c11-enums` separately exercises enumerator values in constant
expressions and runtime code, enum type identity, scope, and constraint
diagnostics. Enumeration constants have type `int`, and the compatible
integer type for each completed enumeration type is signed `int`.

`cephyr.c11-alignment` covers `_Alignas` on objects and record members,
`_Alignof`, `max_align_t`, and integer-constant-expression `offsetof` with
nested named members and constant in-bounds array subscripts. Fundamental
alignments through 16 bytes are supported; alignments greater than 16 bytes
are not. Object redeclarations are checked within a translation unit.

The sample also checks §5.1.2.2 startup and normal termination with two independently
compiled translation units, as well as assertion diagnostics, file positioning,
pushback, and wide character classification through the bundled runtime.
It links on all bundled targets and executes on matching hardware or with the
configured emulators.

This is a regression test, not a conformance suite. The native MachineIR
verifier bounds functions to 4,096 basic blocks, with separate instruction,
value, and verification-work limits. Other known limits include the 64 KiB
stack-frame limit on AMD64 and AArch64 and incomplete support for aggregate
types and ABI.
Further limitations are listed in the [README](README.md#current-limits).

| C11 clauses | Coverage and known gaps |
| --- | --- |
| §5.1.1.2, §6.4, §6.10 | Trigraphs, line splicing, macro expansion, inclusion, line remapping and basic pragmas are implemented. Preprocessing conditions use `intmax_t`/`uintmax_t` conversions, short-circuit evaluation, and numeric character escapes. UTF-8 and universal character names can spell macro and local identifiers; file-scope object and function names remain ASCII-only. `STDC` pragma placement and target-specific wide characters in preprocessing conditions are incomplete. |
| §6.2–§6.9 | Native integer and pointer code, enums, fixed-signature calls, integer/pointer variadic calls, fixed arrays, `_Generic` for supported types, and control flow are supported. AMD64 and AArch64 also support native scalar FP arithmetic, comparisons, conversions, objects, and fixed-signature calls. Structures and unions with supported members have native storage, alignment specifiers, member access, copy, and positional and designated initialization. Structures can have a trailing flexible array, whose elements are not part of the fixed header. By-value aggregate calls and returns, bit-fields, anonymous members, volatile accesses, variably modified types, and general wide literals remain unsupported. |
| Clause 7 | The static Linux runtime includes buffered narrow streams, unformatted wide I/O, wide strings and integer conversions, UTC calendar/time functions, and C-locale character conversions and classification. The archive's nonlocal jumps are for externally compiled C; the Cephyr frontend does not model returns-twice calls. Formatted wide I/O, floating text conversions, math, and signals remain missing. |

## Conformance milestones

1. **Freestanding language and headers (clause 4):** Cover the mandatory
   language constructs on each claimed target, including `long double`,
   aggregate calls and returns, volatile accesses, and variadic function
   definitions with `<stdarg.h>`. Keep the §5.2.4.1 translation and
   execution fixture passing while expanding its semantic coverage. C11
   allows the documented §6.10.8.3 opt-outs for conditional features, not
   opt-outs for these mandatory facilities.
2. **Hosted library and startup (clauses 5 and 7):** Complete the required
   library for the features each target claims, and verify it end to end
   with Cephyr-generated callers, not just the compiler that builds the
   runtime archive. Freestanding conformance would not imply hosted
   conformance.
3. **Diagnostics and implementation choices:** Check syntax and constraint
   diagnostics (§5.1.1.3) and document implementation-defined behavior,
   locale choices, and extensions (clause 4 and Annex J). Do not treat the
   predefined macros or a passing regression suite as evidence of complete
   conformance.
